# リールの作り方（enovloom）

ゴールは「店長が見て、自分の店のことだと思い、プロフィールの note を開く」こと。
再生数だけでなく、保存・シェア・プロフィールへのアクセス・note の閲覧と購入まで見る。

道具はリポジトリの `tools/reel-drama/`。素材と台本さえあれば、仕上げ・チェック・予約はここで全部できる。
1本ごとの焦点の決め方・冒頭3案・編集表・冒頭プレビューから始める進め方・渡すものは、**reel-director スキル**に従う。
試作は `tools/reel-drama/drafts/<id>/`（例 `drafts/honne-01/`: brief.md、エピソード JSON、仮素材、540px の確認用コピー）。

## 流れ

1. ネタを選ぶ … `tools/reel-drama/neta.md` から。1本につき「解決する悩み」と「案内する note」を1つずつ決める
2. フォーマットを選ぶ … 下の F1〜F5
3. 台本を書く … 下の「台本のルール」を全部満たすまで直す
4. 素材をそろえる … お店の写真・動画が第一。AI 映像は補助（下の「素材」）
5. エピソード JSON を書いて書き出す … `node drama.js episodes/<id>.json <素材フォルダ> video.mp4`
6. チェック … `node check.js video.mp4`。WARNING が出たら直す。コマ一覧の画像を目で見る
   試作ができたら、ChatGPT に見直してもらう資料も必ず出す: `node review.js video.mp4 <json> drafts/<id>/review drafts/<id>/brief.md`
   （1秒・3秒・5秒の画面を別々の JPEG（1080x1920、字幕が読める大きさ）、全体の台本と各カットの開始・終了秒、仮素材と未確認の項目を書いた review.txt）。
   仮素材の写真・動画はエピソード JSON の clip に `placeholder: true` と `want`（本番で使いたいもの）を書いておく。図解は `cuts`（t0, t1, narration, role, material）を書く
7. キャプション … 下の「キャプションの型」
8. 予約 … `queue/<id>/post.json` と `caption.txt`、`media/<id>/video.mp4`。**本人の OK が出るまで `"approved": false`**
9. 測定 … `stats/insights.json`（`cloud/insights.ps1` が毎日記録）。週に1回、型ごとに比べて次の台本に反映

## フォーマット

### F1 建前と本音（いちばん伸ばしたい型）
店でよくある一言を、口で言うこと（建前）と頭の中（本音）の2段で見せる。笑い＋「わかる」で広がる。
- 0〜3秒: 見出し（`hook`）「店長の『◯◯』／スタッフの頭の中」＋店長の一言（`pos: "upper"`, `sfx: "pop"`）
- 1ペア 3.5〜4.5秒 × 3ペア: 建前（`tag: "建前"`, `pos: "upper"`）→ 1〜1.5秒後に本音（`tag: "本音"`、オチの効果音 `gaan` / `tsukkomi` / `don`）
- 最後: 中央カード「…じゃあ、どう聞けば本音が出るの？」（`who` なし、`sfx: "whoosh"`）→ 最後の画面で答えの note へ
- `bgm: "comedy"`。本音は短く、言い切る。悪口や人格否定にはしない（笑えるのは「わかる」まで）

### F2 店長あるある 3連
「店長あるある」を3つ、1つ3〜4秒で畳みかける。最後の1つだけ少し刺さるものにして、note につなぐ。

### F3 声かけ Before / After
同じ場面で ✕ の声かけ → ○ の声かけ。○ のあとに相手の反応が変わるのを見せる。説明は字幕1行まで。

### F4 1分ドラマ（30〜45秒）
連続ものにして、1話で全部は解決させない。型は2つ（ChatGPT の分析、2026-10-31）。
- **A 断罪・逆転型**（拡散向き、店長の集客と合うかは未確認）: 理不尽な人物 → 被害が広がる → 証拠や味方が出る → 悪役が負ける
- **B 善意・誤解型**（販売向きの仮説、まだ実証なし）: 良かれと思った行動 → 相手が反発 → 隠れた理由が分かる → 関わり方を変える
- 最初の2秒で「事件」を見せる（例: 封筒を受付台に叩きつけて「辞めます」）。静かな会話から始めない
- 2〜3秒でカットを切り替える。8秒の素材は `start` と `dur` で2〜3本に分けて使う
- 見え方が変わる「瞬間」を必ず入れる（ノートを開く、本当の理由を聞く、など）

### F6 図解（ナレーション＋図）
人物の写真や映像がなくても作れる。困っている場面 → 振り返りの一文 → 図（2つの領域、変更前と変更後など）→ 持ち帰る行動。
`explainer.html`（`style: "explainer"`、`render.js` で書き出す）。例 `drafts/first-reel/`（reel-director の同梱例を試作したもの）。
ナレーションは本人のボイスメモが届いたら重ね、図の出るタイミングを声の区切りに合わせる。

### F5 チャット型
LINE 風の会話（`render.js`、例 `episodes/chat-ep1.json`）。手軽だが伸びていないので、F1〜F4 の補助に使う。

## 台本のルール
- **最初の1秒で状況と感情が分かる**こと。立っているだけ、説明から入る、はやめる
- **1本1メッセージ**。悩み1つ、案内する note 1つ
- 字幕は**1行15文字まで、2行まで**。表示時間は「1文字0.15秒＋0.5秒」以上（`check.js` が見る）
- 本音・オチは短く言い切る。オチには効果音（`gaan` `tsukkomi` `don`）
- 動画の中でノウハウを説明しない。答えはキャプションと note に回す
- 最後は解決しきらない。「この店長、どうしたの？」「どう聞けばいいの？」と思わせる
- 最後の画面には「何が手に入るか」を書く（例: 「スタッフが本音を言える聞き方3つ」）。「続きはこちら」だけにしない
- 店長自身の体験を入れるときは、本人に確認した事実だけ。分からないことは書かない

## 素材

### お店の写真・動画（第一候補。AI っぽさがない）
- 縦向き、JPEG（iPhone の HEIC はそのままだと読めないので JPEG で送ってもらう）
- 顔は出さなくてよい。手元、後ろ姿、受付、マシン、芝、鏡、入口、ロッカー、時計、カレンダー、スマホ画面（個人情報なし）
- **お客様が写っているものは使わない**。スタッフは本人の OK があるものだけ
- 月1回15分の撮影で30本ほどストックし、台本を変えて使い回す

### AI 映像（Google Flow / Veo 3.1。補助として）
- 固定キャストの参考画像（店長・ミオ・ジム）を「素材」に入れる。人物を先に入れる
- しゃべる動作と「しゃべらない」を同じプロンプトに書かない（音声が作れず失敗する）。表情としぐさで書く
- 動く向きは「最初はどこ → 最後はどこ」で書く（出ていく／入ってくるを取り違えやすい）
- 実在の芸能人やブランドロゴは入れない。文字（看板・名札）は崩れるので「No text, no logos, no signs」
- 黒帯・勝手な声・溶けるような切り替わりが入ることがある → 編集で直せる（下の JSON の `start` `dur` `mute`、黒帯は自動）
- 透かしはアカウント設定「可視透かし」をオフ。1本 Fast 20 クレジット、Quality 100。クレジットは毎月リセット

## エピソード JSON（`tools/reel-drama/episodes/`）
- `style: "drama"`、`fps: 30`、`label`（左上の小さい文字）、`bgm`（`pad` / `comedy` / `none`）
- `hook`: `{ until, lines: [1行目, 黄色の2行目] }`（1行だけでもよい）
- `clips[]`: `file`（動画か写真）、`dur`、動画は `start` `mute` `fadeIn` `focusX/Y` `crop`、写真は `move`（none/in/out/left/right/up/down）`fit: "blur"`（横向き写真をそのまま見せる）`dim`（ぼかして暗くし、文字カードの背景にする）
- `subs[]`: `t` `until` `text`、`who`（話す人。店長は青、ほかはピンク）、`tag`（建前／本音）、`pos: "upper"`、`tone: "accent"`、`sfx`（pop, tsukkomi, don, gaan, kira, whoosh, ding, buzz）。`who` も `tag` もない行は中央のカード
- `audio[]`: `{ file, t, gain }` ボイスメモなどを重ねる（素材フォルダに置く）
- `endDur` と `end`（`title` 2行、`question`、`cta`、`note1`、`note2`）。書かなかった項目は表示されない。誘導は1つに絞る
- 例: `episodes/honne-sample.json`（F1）、`episodes/drama-ep1.json`（F4、AI 映像）

図解（F6）は別の形式: `style: "explainer"`, `template: "explainer.html"`, `duration`, `label`, `bgm`, `sfx: [{ t, name }]`, `items[]`。
item は `type`（text / avatar / card / bubble / zone / formula）、`t0` `t1`、`x` `y`（`w` `h`）。text は `size` `align` と `[[強調]]`、
card は `from` `to` `move: [開始, 終了]`、zone は `style`（solid / dashed）`tag` `quote` `quoteT`、formula は `{{白い箱}}` と `[[黄色い箱]]`。
`fadeTo: { t, opacity }` で薄くし、`moveTo: { t, dur, dy, scale }` で動かして縮める。
書き出しは `python3 audio.py <json> audio.wav && node render.js <json> audio.wav video.mp4`。

## チェック（書き出すたびに）
`node check.js video.mp4` が、長さ・1080x1920・30fps・音の有無・音量（-14 LUFS 前後）・黒帯を調べ、コマ一覧の画像を作る。
`drama.js` も字幕のはみ出しを WARNING で出す。そのうえで目で見る:
- 最初の1秒で何の話か分かるか／字幕が顔や大事な所にかぶっていないか
- 実在の人・ブランドロゴ・お客様が写っていないか／AI 映像なら変な動き（分身・溶け）がないか

## キャプションの型
1. 1行目: 動画の一番刺さるセリフ（「」で）
2. 状況を1〜2行
3. 店長の体験（本人に確認した事実だけ）
4. 問いかけ「あなたなら？コメントで教えてください👇」
5. 注記「※よくある場面をもとにした創作です」。AI 映像を使ったら「映像はAIで作成しています」も
6. 導線「◯◯は、プロフィールのリンクのnoteで書いています。」
7. ハッシュタグ8個前後（#店長 #店長あるある #部下育成 #人材育成 #ジム経営 など）

## 予約と投稿
- `queue/<id>/post.json`: `type: "reel"`, `publishAt`（JST で `+09:00`）, `approved`, `media: ["video.mp4"]`, `thumbOffsetMs`, `captionFile`
- 投稿は GitHub Actions の autopost（`cloud/publish.ps1`）。予定から12時間を過ぎると missed になる
- 本人は PC から queue を同期していることがある。main に直接入れる前に、同期で消えないか本人に確認する
- 投稿が止まったら: Actions のログを見る。`(#200) Cannot call API ... on behalf of user` はトークンが拒否されている。Facebook に本人がログインして確認事項がないか見る → 直らなければページトークンを作り直して `IG_PAGE_TOKEN` を更新

## 測定
- `cloud/insights.ps1`（workflow `insights`）が、投稿ごとの再生・リーチ・保存・シェア・いいね・コメント・平均視聴時間と、アカウントのプロフィール閲覧・リンクのタップを `stats/insights.json` に記録する
- トークンに `instagram_manage_insights` の許可が要る。ないときはその旨を記録して止まらない
- 週に1回: フォーマット（F1〜F5）ごとに保存率・シェア率・プロフィール閲覧を比べ、伸びた型を増やす
