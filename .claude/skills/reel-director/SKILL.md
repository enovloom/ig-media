# リールの構成・編集

## 目的と範囲

視聴者が自分に関係する話だと理解でき、具体的な行動を一つ持ち帰れる短いリールを作る。
再生数や売上の向上は仮説として扱う。このスキルは台本と編集の制作手順であり、動画生成モデルや編集ソフトそのものではない。
既存のプロジェクトにある編集手段を調べて使う。新しいサービス契約や有料API呼び出しを、このスキルだけを根拠に実行しない。
依頼の対象は試作と改善。公開、予約投稿、既存の自動運用設定の変更は別の明示指示がある場合に限る。

## 1. 今あるものを確認する

- 作業先のCLAUDE.md / AGENTS.mdなどの指示を読む。
- 指定された台本、素材、編集コード、過去の制作指示を確認する。存在しないファイルや未確認の映像を、確認済みとして扱わない。
- 字幕、カットの順番、各素材の使用時間、音声の有無、書き出し方法を整理する。
- 本人の経験・実績・発言は確認できた資料に限定する。説明のための架空例は、実話と区別する。
- 実際に観察した問題と推測を分ける。ユーザーがすでに挙げた問題を再質問しない。

## 2. 一本の焦点を決める

次の四つを短く書く。

1. 誰の、どんな具体的な場面に向けるか。
2. 視聴者が今つまずいていることは何か。
3. 見終えた人が使える言い方・行動は何か。
4. その行動を伝えるために必要な事実や例は何か。

一つのリールに複数の教訓を詰め込まない。一般論を述べるだけで終えず、具体的な言い方や動作を一つ入れる。
冒頭で約束した内容には、動画の中で答える。

## 3. 冒頭と話の順番を設計する

- 冒頭の案を三つ作り、視聴者との関係の分かりやすさ、具体性、事実との整合性から一つ選ぶ。
- 挨拶、長い自己紹介、ロゴだけの画面を冒頭に挟まない。
- 「知らないと損」「絶対」「全員」などの根拠のない煽りや、相手を責める決めつけを使わない。
- 悩みが分かる場面 → 気づき・確認点 → 具体例 → 持ち帰る行動を、一つの話としてつなぐ。この順序は内容に応じて調整する。
- 初回は15〜25秒を仮の目安にする。固定尺に合わせて読み上げを不自然に速めない。実際の音声ができたら尺を調整する。
- 保存・フォロー・プロフィールへの誘導を全部重ねない。今回の目的に必要なら、一つだけ自然に置く。

## 4. 編集表を先に作る

秒数 / ナレーション / 画面の文字 / 見せる動作や図 / 使用素材と使用区間 / その映像の役割、の表を作る。
各カットは「この映像が、セリフのどの意味を伝えるか」を説明できるようにする。

映像の役割の例：

- 仕事を任せた場面を短い動作で見せる。
- 判断できる範囲と相談する範囲を、二つの領域で示す。
- 変更前と変更後の言い方を、順番に見せる。
- 実際のメモや画面を使って、行動を具体化する。

職場の風景などの雰囲気素材を、説明全体の背景として流し続けない。
カットは意味や動作の変化に合わせて切り替える。機械的に一定秒数で切り替えない。
文字を読む、図を理解する、セリフが届くための間を残す。

## 5. 足りない素材を具体化する

- まず手元の素材で、必要な意味を伝えられるかを確認する。伝えられる素材は再利用する。
- 動画、実写、図解、文字の動きを、伝える内容に合わせて選ぶ。
- Flow用の生成指示には、主役、動作、場所、画角、光、縦横比、必要な場面を記す。
- 同じ人物・場所を使う場合は、共通の参照素材を指定する。参照画像がなければ、あるふりをしない。
- 編集で加える日本語字幕や図中の文字は、原則として映像生成と分けて管理する。
- 素材ごとに「最終動画のどこで使うか」を記す。素材の生成尺と、最終的な使用秒数は区別する。
- 利用できるFlowの機能や生成尺を確認する。存在しない機能や未契約のAPIを前提にしない。
- 自動生成との接続がなければ、Flowに貼るプロンプトを作成し、生成済みと主張しない。

## 6. 冒頭の試作から編集する

1. 編集表と、冒頭約5秒のプレビューを先に作る。既存の編集手段を使う。
2. 冒頭で問題が分かるか、字幕が読めるか、意味のない待ち時間がないかを確認し、直す。
3. 利用できる素材がそろっていれば、全体の試作まで進める。新たな承認手順を独自に増やさない。
4. 素材が足りない場合は、仮素材の箇所を明示し、実写や生成素材があるように装わない。
5. 元素材を保持し、試作を別名で書き出す。

字幕は意味のまとまりで改行し、スマートフォンで読める量と大きさにする。
画面内の説明文字と字幕が重複しすぎないようにする。
重要な文字をInstagramの操作表示と重なりやすい端に寄せない。可能なら実際の表示で確認する。
音楽や効果音は声を聞き取りやすい音量にし、目的のない効果音・ズーム・トランジションを追加しない。

## 7. 書き出したものを確認する

書き出し成功と、内容が伝わることを別々に確認する。

- 実ファイルから、再生時間、寸法、ファイルサイズ、音声トラックの有無を確認する。
- 書き出したフレームで、文字切れ、改行、素材の位置を確認する。
- 動画再生や音声確認が可能なら、間、切り替え、読み上げとの同期、聞き取りやすさを確認する。
- 静止画だけではテンポや音声は確認できない。確認できなかった項目は未確認と記す。
- 作ったコードや台本だけを見て、映像や音声まで検証済みとしない。
- 実測の視聴時間、保存数、シェア数などがあるときだけ引用する。制作側の自己評価を、投稿後の成果と混同しない。

## 8. 渡すもの

プロジェクトの慣習に合わせて、試作用フォルダに次を保存する。

- 今回の対象視聴者と持ち帰る行動
- 採用した台本と、別案の冒頭二つ
- 秒数と素材の使用区間が分かる編集表
- 必要な場合のみ、Flow用の素材生成指示
- 冒頭プレビューと、作成できた範囲の全体試作
- 確認したこと、未確認のこと、次に変える一点

容量が大きくて共有できない場合は、元ファイルを保持したうえで、小さい確認用コピーを作る。
既存環境で可能なら、アスペクト比を維持した縦動画の横幅540px程度、H.264 MP4、音声付き、10MB以下を目標にし、実際のサイズを測る。
収まらなければ冒頭10秒版にする。これは共有用の目標であり、アップロードできる保証ではない。
動画を共有できないときの補助として、時刻付きの数コマの画像と台本テキストも用意できる。静止画で確認できる範囲には限界がある。

## 同梱例

`first-reel.txt` は「判断できる範囲も渡す」を扱う架空の説明例。
そのまま本人の実体験として扱わない。今回の投稿テーマに合う場合にのみ使う。
`flow-prompts.txt` は、この説明例に必要な素材一つの生成指示。追加生成が必要な場合だけ使う。
